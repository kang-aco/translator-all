# 실시간 통번역기

컴퓨터에서 나오는 소리(유튜브·CNN·화상회의 등)를 받아 적고, 그 자리에서 번역해
자막으로 보여주는 개인용 웹앱입니다. 브라우저만 있으면 되고 설치할 프로그램도,
로그인도 없습니다. 자막은 별도의 작은 창(PiP)으로 띄울 수 있어서 다른 창에서
일하는 동안에도 화면 맨 위에 계속 떠 있습니다. 받아쓰기는 크롬에 내장된 음성 인식을
쓰고(무료), 번역은 Gemini에게 앞뒤 맥락과 함께 맡겨 구두점 없는 받아쓰기 결과를
문장 단위로 나눠 옮깁니다. 번역 API 키는 브라우저가 아니라 Cloudflare 서버에만
있으므로 키가 노출되지 않습니다.

## 1. 처음 설정하는 법

순서대로 하세요. 앞 단계가 안 되면 뒤 단계는 의미가 없습니다.

### 1-1. VB-CABLE 설치 — 컴퓨터 소리를 마이크처럼 만들기

> **왜 필요한가**
> 브라우저의 음성 인식은 **마이크로 들어오는 소리만** 알아듣습니다. 유튜브 소리는
> 스피커로 나가는 소리라 그냥은 못 듣습니다. VB-CABLE은 "가상 오디오 케이블"입니다.
> 컴퓨터 안에 눈에 안 보이는 선을 하나 놓아서, 스피커로 나갈 소리를 마이크 입력으로
> 되돌려 넣어 줍니다.

1. <https://vb-audio.com/Cable/> 에서 VB-CABLE을 내려받아 설치합니다.
   압축을 풀고 `VBCABLE_Setup_x64.exe`를 **관리자 권한으로 실행**한 뒤 재부팅합니다.

2. **출력을 CABLE Input으로 바꿉니다.**
   `설정 → 시스템 → 소리 → 출력`에서 **CABLE Input**을 고릅니다.
   → 이 시점부터 스피커에서 소리가 안 들립니다. 정상입니다. 다음 단계에서 되살립니다.

3. **내 귀로도 들리게 합니다.**
   `설정 → 시스템 → 소리 → 추가 사운드 설정`(제어판 소리 창)을 엽니다.
   **녹음** 탭 → **CABLE Output** 두 번 클릭 → **듣기** 탭 →
   **이 장치로 듣기** 체크 → 아래 목록에서 **실제 스피커/헤드폰**을 고르고 확인.
   → 다시 소리가 들립니다.

   > 소리가 약간 늦게 들릴 수 있습니다. 같은 창의 **고급** 탭에서 샘플 속도를
   > 스피커와 같게 맞추면 나아집니다.

### 1-2. 크롬 마이크를 CABLE Output으로 지정

1. 크롬 주소창에 `chrome://settings/content/microphone` 입력
2. 맨 위 드롭다운에서 **CABLE Output (VB-Audio Virtual Cable)** 선택
3. 앱 페이지를 열고 `시작`을 누르면 마이크 권한을 묻습니다. **허용**하세요.

> 다시 평소처럼 쓰려면 1-1의 2번을 원래 스피커로 되돌리면 됩니다.

### 1-3. Google 번역 API 키 발급 (예비용)

Gemini가 한도 초과나 오류로 실패할 때 자동으로 대신 써주는 안전망입니다.
없어도 앱은 돌지만, 있으면 자막이 끊기지 않습니다.

1. <https://console.cloud.google.com/> 접속 → 프로젝트 생성
2. `API 및 서비스 → 라이브러리` → **Cloud Translation API** 검색 → **사용 설정**
3. `API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키`
4. **★ 만든 키를 눌러 제한을 겁니다** (안 하면 키가 새어나갔을 때 요금 폭탄)
   - `API 제한사항` → **키 제한** → **Cloud Translation API**만 체크
5. **★ 할당량도 겁니다**
   - `IAM 및 관리자 → 할당량` → `Cloud Translation API` 검색
   - `v2 and v3 general model characters per day` 를 **15000** 정도로 낮춤
   - 설정 화면의 사용량 게이지도 이 15,000자를 기준으로 그려집니다

### 1-4. Gemini 키 발급 (무료 등급)

1. <https://aistudio.google.com/apikey> 접속
2. **Create API key** → 키 복사
3. 무료 등급을 쓰려면 **결제를 연결하지 않은 프로젝트**에 만드세요.
   결제가 붙으면 유료 등급으로 넘어갑니다.

> 무료 등급은 글자 수가 아니라 **분당·일당 요청 횟수**로 제한됩니다.
> 자막을 켜두면 30초에 8번쯤 부르므로 한도에 닿을 수 있습니다.
> 그러면 화면 위에 `번역 한도 초과 — 구글 번역으로 전환됨` 배지가 뜨고
> 자동으로 구글 번역으로 넘어갑니다.

### 1-5. Cloudflare Pages 배포와 환경변수

1. <https://dash.cloudflare.com/> → `Workers & Pages` → `Create` → `Pages`
   → `Connect to Git` → 이 저장소 선택
2. 빌드 설정: **빌드 명령 없음**, 출력 디렉터리 `/` (빌드 도구를 쓰지 않는 앱입니다)
3. `Settings → Variables and Secrets`에서 아래 4개를 넣습니다.

| 이름 | 값 | 종류 |
|---|---|---|
| `GEMINI_API_KEY` | 1-4에서 받은 키 | **Secret** |
| `GOOGLE_TRANSLATE_API_KEY` | 1-3에서 받은 키 | **Secret** |
| `TRANSLATE_ENGINE` | `gemini` | Text |
| `LLM_MODEL` | `gemini-3.1-flash-lite-preview` | Text |

> **★ Production과 Preview 양쪽에 모두 넣으세요.**
> Cloudflare는 환경을 둘로 나눠 관리합니다. Production에만 넣으면
> 미리보기 배포에서 `서버에 번역 API 키가 등록되어 있지 않습니다` 오류가 납니다.

4. 환경변수를 바꾼 뒤에는 **반드시 다시 배포**해야 반영됩니다.
   (`Deployments` → 최신 배포 → `Retry deployment`)

5. 확인: 배포된 주소를 열고 **채팅 탭**에서 아무 문장이나 번역해 보세요.
   결과 카드 아래에 `엔진: gemini`가 뜨면 성공입니다.
   `엔진: google`이 뜨면 Gemini 쪽이 실패한 것이니 [4장](#4-문제가-생겼을-때)을 보세요.

### 되돌리기

Gemini를 끄고 예전처럼 구글 번역만 쓰려면 **`TRANSLATE_ENGINE` 하나만 지우고**
다시 배포하면 됩니다. 나머지는 그대로 둬도 됩니다.

## 2. 파일 구조

```
index.html            화면 구조(HTML) + 스타일(CSS) + script 태그 6줄
js/                   자바스크립트 (부르는 순서 = 의존 관계)
functions/api/        Cloudflare 서버에서 도는 코드
```

### 브라우저에서 도는 코드

script 태그의 **순서가 곧 의존 관계**입니다. 순서를 바꾸면 깨집니다.
(`index.html`의 script 태그 부분에 이유가 주석으로 적혀 있습니다.)

| 순서 | 파일 | 역할 | 손대기 위험도 |
|---|---|---|---|
| ① | `js/config.js` | 조절 상수 전부 + 화면 요소 모아두기(`$`, `captionsEl`…) | 낮음 |
| ② | `js/speech.js` | 음성 인식, 자동 재시작, **감시견**, `markEvent`, `lastEventAt` | **매우 높음** |
| ③ | `js/chunker.js` | 중간 결과 자체 끊기 (크롬이 확정을 미루는 문제 대응) | 높음 |
| ④ | `js/translate.js` | 번역 호출 창구, 디바운스, 맥락, 오류 배지, 채팅 모드 | 보통 |
| ⑤ | `js/subtitle.js` | 자막 그리기, 줄 수 유지, **PiP 창 전체** | **높음** |
| ⑥ | `js/app.js` | 언어 목록, 설정 저장/복원, 모드 전환, 이벤트 연결, `init()` | 보통 |

> **왜 `app.js`가 맨 마지막인가**
> `app.js`의 "이벤트 연결"이 `startBtn.addEventListener('click', startListening)`처럼
> 다른 파일의 함수를 **이름으로 바로** 가리킵니다. 그 파일이 아직 안 불렸으면
> `ReferenceError`가 나고 그 아래 코드가 통째로 안 걸립니다.
> 같은 이유로 `$`와 화면 요소는 `config.js`에 있습니다. `translate.js`와
> `subtitle.js`가 불러오는 즉시 `$`를 쓰기 때문입니다.

> **ES 모듈(`import`/`export`)을 쓰지 않습니다.**
> 모듈로 만들면 변수가 파일 안에 갇혀 F12 콘솔에서 `INTERIM_CUT_CHARS = 50` 같은
> 시험을 못 하게 됩니다. 평범한 `<script>`로 두면 모든 값이 전역에 남습니다.

### 서버에서 도는 코드

| 파일 | 역할 |
|---|---|
| `functions/api/translate.js` | `POST /api/translate` 중계기. **API 키를 읽을 수 있는 유일한 곳** |

브라우저는 번역 API를 직접 부르지 않고 항상 같은 사이트 주소인 `/api/translate`만
부릅니다. 키는 Cloudflare 환경변수에만 있고 브라우저로 내려가지 않습니다.
엔진 선택 순서는 `TRANSLATE_ENGINE` 강제 지정 → DeepL → Google → Gemini이고,
고른 엔진이 실패하면 남은 엔진으로 자동으로 넘어갑니다.

## 3. 조절할 수 있는 값들

전부 **`js/config.js`** 에 있습니다. 파일을 고쳐 배포해도 되고,
**F12 콘솔에서 바로 입력해 즉시 시험**해도 됩니다 (새로고침하면 원래대로).

```js
INTERIM_CUT_CHARS = 50     // 콘솔에 이렇게 치면 바로 적용됩니다
```

### 음성 인식이 죽었는지 감시하는 값

| 상수 | 기본값 | 위치 | 하는 일 |
|---|---|---|---|
| `EVENT_SILENCE_LIMIT_MS` | 7000 | `config.js:28` | 이 시간 동안 인식기에서 **아무 이벤트도 없으면** 죽은 것으로 보고 되살립니다 |
| `WATCHDOG_MS` | 1000 | `config.js:25` | 감시견이 확인하는 **주기** |

- `EVENT_SILENCE_LIMIT_MS`를 **내리면** 더 빨리 되살아나지만, 말이 없어 조용한
  것뿐인데 멀쩡한 인식기를 껐다 켜는 헛수고가 늘어납니다.
- **올리면** 헛수고는 줄지만 진짜 죽었을 때 자막이 멈춰 있는 시간이 길어집니다.
- 실제 감지 시각은 `한계` ~ `한계 + 주기` 사이입니다. 7000 + 1000이므로
  **7~8초 사이**에 잡힙니다. `WATCHDOG_MS`를 3000으로 올리면 7~10초로 벌어집니다.

### 중간 결과를 언제 끊어 번역에 넘길지

> **왜 이런 게 있나**
> 크롬은 말이 길게 이어지면 "이 문장 끝났다"(확정) 신호를 한참 미룹니다.
> 90단어를 확정하는 데 30초가 넘게 걸린 적이 있습니다. 그때까지 기다리면
> 번역이 시작조차 못 하므로, 확정을 기다리지 않고 **우리가 직접 끊어서** 넘깁니다.

| 상수 | 기본값 | 위치 | 하는 일 |
|---|---|---|---|
| `INTERIM_CUT_CHARS` | 70 | `config.js:51` | 아직 안 보낸 글이 이만큼 넘으면 한 덩어리로 끊습니다 |
| `INTERIM_IDLE_MS` | 1500 | `config.js:52` | 중간 결과가 이 시간 동안 안 바뀌면 남은 걸 끊어 보냅니다 |
| `INTERIM_SAFE_TAIL` | 15 | `config.js:53` | 끝에서 이만큼은 손대지 않고 남겨 둡니다 |

- `INTERIM_CUT_CHARS`를 **내리면**(예: 50) 자막이 더 빨리, 더 잘게 나옵니다.
  대신 **번역 호출 횟수가 늘어** Gemini 무료 한도에 더 빨리 닿고, 조각이 짧아
  LLM이 볼 맥락이 줄어 번역 품질이 떨어집니다.
- **올리면**(예: 120) 호출이 줄고 번역이 자연스러워지지만 자막이 늦게 뜹니다.
  **한도 초과 배지가 자주 뜨면 이 값을 올리세요.**
- `INTERIM_SAFE_TAIL`을 **올리면** 더 안전합니다. 크롬은 중간 결과의 **뒷부분을
  계속 고쳐 쓰기** 때문에, 끝까지 잘라 보내면 나중에 바뀔 글자를 틀린 채로
  번역하게 됩니다. 자막에 이상한 낱말이 자주 보이면 25 정도로 올려 보세요.
  대신 그만큼 늦게 나갑니다.
- `INTERIM_IDLE_MS`를 **내리면** 말이 잠깐 멎어도 바로 끊어 보냅니다. 반응이
  빨라지지만 문장이 잘게 쪼개집니다.

### 번역 품질

| 상수 | 기본값 | 위치 | 하는 일 |
|---|---|---|---|
| `CONTEXT_SENTENCE_COUNT` | 3 | `config.js:42` | 직전 원문 몇 개를 **맥락으로 함께** 보낼지 |

- **올리면** 대명사("그", "그것")와 말투가 잘 이어져 번역이 자연스러워집니다.
  대신 보내는 글자 수가 늘어 사용량이 커집니다. (실측: 본문 84자에 맥락 162자가
  붙어 총 246자를 보냈습니다.)
- **내리면**(1 또는 0) 사용량이 줄지만 문장이 서로 따로 노는 느낌이 납니다.

### 화면 표시

| 상수 | 기본값 | 위치 | 하는 일 |
|---|---|---|---|
| `INTERIM_MAX_LINES` | 2 | `config.js:62` | "듣는 중" 회색 줄을 몇 줄까지 보여줄지 (`0`이면 제한 없음) |

나머지 표시 설정(자막 표시 방식, 표시 내용, 줄 수, 최소 표시 시간, 테마, 글자 크기)은
코드가 아니라 **앱의 설정 탭**에서 바꾸고 브라우저에 저장됩니다.

### 권장 설정값

실제로 써보면서 정리한 값입니다. 둘 다 앱의 **설정 탭**에서 바꿉니다.

| 영상 종류 | 표시 줄 수 | 최소 표시 시간 |
|---|---|---|
| 뉴스처럼 한 사람이 말하는 영상 | 2 | 2초 |
| 여러 사람이 대화하는 영상 | 4 | 4~5초 |

대화 영상에서 내용이 빠지는 것처럼 느껴지면 대부분 이 설정 때문입니다.
처리는 다 되고 있는데, 자막이 읽히기 전에 다음 줄에 밀려 사라지는 것입니다.

## 4. 문제가 생겼을 때

### 4-1. 자막이 안 나올 때 — 이 순서로 확인

1. **소리가 들리나?**
   안 들리면 1-1의 3번(이 장치로 듣기)이 풀린 것입니다.

2. **탭에 마이크 표시가 켜져 있나?**
   크롬 탭에 빨간 점이 없으면 인식이 안 돌고 있습니다. `시작`을 다시 누르세요.

3. **크롬 마이크가 CABLE Output인가?**
   `chrome://settings/content/microphone` 확인. 노트북 내장 마이크로 되돌아가
   있으면 방 안 소리를 듣고 있는 것입니다.

4. **원문 자막(흰 글씨)은 나오나?**
   - 나온다 → 받아쓰기는 정상. **번역 문제**입니다. 6번으로.
   - 안 나온다 → 받아쓰기 문제. 5번으로.
   - (설정에서 `표시 내용`을 **원문 + 번역**으로 두면 구분하기 쉽습니다.)

5. **F12 콘솔에 `▸` 줄이 계속 찍히나?**
   - 찍힌다 → 인식기는 살아 있는데 소리가 안 들어오는 것. 1~3번을 다시.
   - 안 찍힌다 → 인식기가 죽은 것. 7~8초 안에 `⚠ 감시견` 이 뜨고 되살아나야
     정상입니다. 안 뜨면 `시작`을 다시 누르세요.

6. **화면 위에 빨간 배지가 떴나?**
   - `번역 한도 초과` → Gemini 무료 한도. 잠시 기다리거나 `INTERIM_CUT_CHARS`를
     올려 호출을 줄이세요.
   - `맥락 번역 모델을 찾을 수 없음` → 모델이 단종된 것. [5장](#5-알려진-제약) 참고.
   - 배지는 없는데 자막 아래가 `google`이면 조용히 대체된 것입니다.

7. **채팅 탭에서 번역해 보기**
   여기서도 안 되면 서버·키 문제입니다. Cloudflare 환경변수 4개와
   재배포 여부를 확인하세요.

### 4-2. 콘솔에서 볼 것

F12 → Console 탭. 네 종류의 줄만 보면 됩니다.

| 표시 | 예시 | 뜻 |
|---|---|---|
| `▸` | `[음성인식 21:03:11.418] ▸ onresult (직전 이벤트로부터 1.2초)` | 인식기가 살아 있다는 증거. 계속 찍혀야 정상 |
| `⚠` | `⚠ 감시견: 7.4초 동안 이벤트가 하나도 없었습니다 → 강제로 되살립니다` | 인식기가 죽어서 되살리는 중. 가끔 나오는 건 정상 |
| `✂` | `✂ 중간 결과 끊음 [길이 70자 초과] 54자 (발화 시작 후 5.1초)` | 확정을 안 기다리고 우리가 끊어 번역에 넘김 |
| `[번역 N초]` | `[번역 1.4초] gemini (gemini-3.1-flash-lite-preview) · 본문 54자 + 맥락 162자 → 문장 2개` | 번역에 걸린 시간과 엔진 |

**체감 지연 = `(발화 시작 후 N초)` + `[번역 N초]`** 입니다. 7초 안쪽이면 쓸 만합니다.

`⚠ gemini 실패로 대체: …` 가 보이면 그 뒤의 HTTP 번호가 원인입니다
(429 = 한도 초과, 404 = 모델 없음, 403 = 권한).

### 4-3. `speechState()` 로 상태 보기

콘솔에 `speechState()` 를 치면 음성 인식의 현재 상태가 한눈에 나옵니다.

```
{
  듣는중_플래그: true,
  사용자가정지함: false,      ← true 면 자동 재시작이 멈춰 있습니다
  마지막이벤트시각: "오후 9:03:11",
  마지막이벤트이후초: "1.2",   ← 7 이상이면 죽은 것
  죽은것으로판단: false,
  한계초: 7,
  총재시작횟수: 3,            ← 계속 늘면 인식이 자주 끊긴다는 뜻
  start예외누적: "0/3",
  네트워크오류누적: "0/3",     ← 3/3 이면 인터넷 문제로 멈춘 상태
  직전오류: null,
  다음재시작지연ms: 200
}
```

**읽는 법**

- `마지막이벤트이후초`가 계속 커지는데 `총재시작횟수`가 안 늘면 → 감시견이 안 돌고
  있는 것. 탭이 오래 숨겨져 크롬이 타이머를 늦춘 경우일 수 있습니다.
- `사용자가정지함: true`인데 정지를 누른 적이 없다면 → 오류가 3번 쌓여 앱이 스스로
  멈춘 것. `시작`을 다시 누르면 됩니다.
- `네트워크오류누적: 3/3` → 인터넷 연결을 확인하고 `시작`을 다시 누르세요.

관련해서 `pipTimerReport()` 도 있습니다. PiP 창을 띄운 채 오래 두었을 때
본 페이지와 PiP 창의 타이머가 제 주기로 도는지 비교해 줍니다.
`억제의심: true` 면 크롬이 타이머를 늦추고 있다는 뜻입니다.

## 5. 알려진 제약

### 브라우저

- **크롬 116 이상에서만 온전히 돕니다.** PiP 창(Document Picture-in-Picture)이
  크롬 116부터 들어갔습니다.
- **파이어폭스·사파리에서는 말하기 모드를 못 씁니다.** 음성 인식이 없습니다.
  접속하면 말하기 탭에 안내가 뜨고 버튼이 막힙니다. **채팅 탭의 글 번역은 됩니다.**
- **모바일은 지원하지 않습니다.** VB-CABLE 같은 가상 오디오 장치를 쓸 수 없고
  PiP 창도 동작하지 않습니다.

### PiP 창

- **창 위치를 지정하거나 기억할 수 없습니다.** 웹 코드로는 불가능합니다.
  매번 크롬이 정하는 자리에 뜹니다.
- **창을 반투명하게 만들 수 없습니다.** `js/subtitle.js`의 `PIP_BG_DARK`
  알파값은 "얼마나 진한 검정인가"만 정할 뿐, 뒤 영상이 비치게 하지는 못합니다.
- 자막 아래 시각·엔진 줄은 PiP 창에서 일부러 감춥니다. 영상 위에 얹는 자막이라
  방해가 되기 때문입니다. 본 페이지에는 그대로 보입니다.

### 번역 품질

- **문장 중간이 잘릴 수 있습니다.** 확정을 기다리지 않고 70자에서 끊기 때문에,
  한 문장이 두 자막에 나뉘어 나올 수 있습니다. LLM에게 "잘린 조각에는 억지로
  마침표를 붙이지 말라"고 지시해 두었지만 완전히 막지는 못합니다.
  거슬리면 `INTERIM_CUT_CHARS`를 100~120으로 올리세요.
- **크롬이 중간 결과를 나중에 고쳐 씁니다.** 이미 번역해 보낸 앞부분이 나중에
  다른 낱말로 바뀔 수 있습니다. `INTERIM_SAFE_TAIL`이 이걸 줄여 줍니다.
- 받아쓰기 자체가 틀리면 번역도 틀립니다. 이건 크롬 음성 인식의 한계입니다.

### API

- **Gemini 모델이 단종되면 404가 납니다.** 그러면 조용히 구글 번역으로 넘어가서
  자막은 계속 나오지만 **맥락 번역이 하나도 안 됩니다.** 화면에
  `맥락 번역 모델을 찾을 수 없음` 배지가 뜨고, 콘솔에
  `⚠ gemini 실패로 대체: Gemini 오류 (HTTP 404)` 가 찍힙니다.

  **고치는 법**: <https://ai.google.dev/gemini-api/docs/models> 에서 지금 쓸 수 있는
  모델 이름을 확인하고, **두 곳을 모두** 바꾸세요.
  1. Cloudflare 환경변수 `LLM_MODEL`
  2. `functions/api/translate.js`의 `DEFAULT_LLM_MODEL` (파일 안에 이력과 주의사항이
     주석으로 적혀 있습니다)

  환경변수만 바꾸고 기본값을 두면, 나중에 다른 곳에 새로 배포했을 때 같은 일이
  되풀이됩니다.

- **Gemini 무료 등급은 요청 횟수 제한이 있습니다.** 자막을 켜두면 30초에 8번쯤
  부르므로 한도에 닿을 수 있습니다. 한도를 넘으면 구글 번역으로 자동 전환되고
  자막은 계속 나옵니다.
- 설정 화면의 사용량 게이지(15,000자)는 **구글 번역 기준**입니다. Gemini는 글자 수가
  아니라 요청 횟수로 제한되므로, 게이지는 "얼마나 보냈나" 참고용으로만 보세요.

### 기타

- **탭 타이머 억제 — 실측 결과 문제없음.**

  크롬은 오래 숨겨진 탭의 타이머를 늦춥니다(5분이 넘으면 1분에 한 번 수준까지).
  그렇게 되면 감시견이 제때 못 돌아 인식기가 죽어도 한참 뒤에야 되살아납니다.
  다른 창에서 일하며 자막만 보는 것이 이 앱의 주 용도라 걱정되는 부분이었습니다.

  **PiP 창을 띄우고 브라우저를 최소화한 채 10분 방치해 재봤더니 억제가 걸리지
  않았습니다.**

  | | 평균 | 최대 |
  |---|---|---|
  | 본 페이지 | 1000ms | 1018ms |
  | PiP 창 | 1000ms | 1018ms |

  1초 주기 타이머가 10분 내내 제 주기를 지켰습니다. **마이크를 캡처 중인 탭이라
  크롬이 억제 대상에서 빼준 것으로 보입니다** (크롬은 소리를 내거나 오디오·영상을
  캡처 중인 탭을 억제에서 제외합니다). 확정된 원인은 아니고 추정입니다.

  **확인하는 법**: 콘솔에 `pipTimerReport()` 를 치면 본 페이지와 PiP 창의 실제
  타이머 간격을 비교해 줍니다. `억제의심: true` 이거나 `최대ms` 가 3000을 넘으면
  억제가 걸린 것입니다.
  ※ **개발자도구를 열어둔 채로 방치하면 안 됩니다.** 크롬은 개발자도구가 열린
  페이지에는 억제를 걸지 않으므로 결과가 무의미해집니다. 방치가 **끝난 뒤에** F12를
  여세요. 측정값은 메모리에 계속 쌓이므로 나중에 열어도 그대로 남아 있습니다.

  **크롬 정책이 바뀌어 억제가 걸리게 되더라도 대비는 되어 있습니다.** PiP 창은
  항상 화면에 보이는 창이라 그 안의 타이머는 늦춰지지 않습니다. 그래서 백업
  감시견을 PiP 창 쪽 타이머로 돌려 두었습니다(`js/subtitle.js` 의 `pipTick`).
  본 페이지 감시견이 늦춰지더라도 이쪽이 1초마다 확인해 대신 되살립니다.
  본 페이지 감시견 코드는 건드리지 않았고, 백업은 같은 판단 기준
  (`lastEventAt` 이후 `EVENT_SILENCE_LIMIT_MS` 경과)으로 기존
  `reviveRecognition()` 을 부를 뿐입니다. 둘이 겹쳐도 중복 실행은 막혀 있습니다.
- 설정과 사용량은 브라우저의 `localStorage`에 저장됩니다. 다른 브라우저나 다른
  컴퓨터에서는 처음 상태로 시작합니다.
